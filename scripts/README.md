# Build scripts

Run them from any directory. Everything they build is copied into `dist/` at the repo root.

| Script | What it does |
|---|---|
| `build-firmware.sh [-t TARGET]` | Builds the firmware → `dist/espkbd-firmware-<target>.bin` (merged image, flash at `0x0`) |
| `flash-firmware.sh [-t TARGET] [-p PORT] [--monitor]` | Builds and flashes the firmware, then optionally opens the serial monitor |
| `test-firmware.sh` | Firmware host unit tests (`firmware/test/host`) |
| `build-apk.sh [debug\|release]` | Android APK → `dist/espkbd-<type>.apk` (release is unsigned) |
| `build-desktop.sh [dmg\|msi\|deb]` | Desktop package → `dist/`. The default matches the current OS, and each format builds only on its own OS |
| `test-app.sh` | App unit tests (`:shared:jvmTest`) |
| `build-all.sh [-t TARGET] [--skip-tests]` | Runs all tests, then firmware + APK + desktop package |

## Firmware target

`-t/--target` picks the ESP chip. It falls back to `$IDF_TARGET`, then to `esp32s3`. Each target builds
in its own `firmware/build-<target>/` with its own sdkconfig and dependency lock, so `firmware/sdkconfig`,
`firmware/dependencies.lock` and the IDE's `firmware/build/` are never touched. The firmware needs native USB (TinyUSB), so only `esp32s2`,
`esp32s3` and `esp32p4` make sense.

## Prerequisites

- **Firmware:** ESP-IDF v6.1. The scripts never search outside the repo. Either `idf.py` is already
  on `PATH`, or one of these is set:
  - `IDF_EXPORT`: an activate/export script to source (e.g. the one generated by EIM)
  - `IDF_PATH`: the ESP-IDF checkout; `$IDF_PATH/export.sh` is sourced
- **App:** JDK 21. The Android SDK comes from `ANDROID_HOME` or `app/local.properties`.

| Env variable | Used for |
|---|---|
| `IDF_EXPORT`, `IDF_PATH` | Finding ESP-IDF (see above) |
| `IDF_TARGET` | Default firmware target |
| `ESPPORT` | Default serial port for `flash-firmware.sh` (idf.py autodetects otherwise) |

iOS isn't covered. Build it from Xcode (`app/iosApp`).
